# Comparing complete QED rates through nine points

The study covers all 18 families from annihilation into two photons to production with four charged pairs and one real photon. Each exported process contains every labeled photon helicity. The two SPINAS prescriptions use model 4 (physical) and model 5 (spurious) through eight legs. Nine-point input comes from the completed constructors. Its manifest must select the requested pole preference for every helicity, including the all-positive sector. A common phase of a parity branch drops out after its modulus is squared.

## Read the measurements

- `rate-study.json` contains the per-family counts, construction receipts and times, generated byte counts, point weights, relative residuals and individual sweeps. Construction uses the latest successful 100,000-point row for each charged family, helicity count up to parity, and pole preference. `VALID_SCORE_UNAVAILABLE` identifies a validated result whose expanded score was not measured.
- `catalog-study.tex` and `rate-survey.tex` are the manuscript sections. Run `python3 render-rate-study.py OUTPUT` with Matplotlib 3.8 or newer to write the underlying CSV, four tables and four vector figures into OUTPUT. The optional patch in `catalog-main.patch` applies the associated title, scope and section changes to the previous nine-point manuscript. Copy the two manuscript sections next to the draft before rebuilding it. The paper uses both current measurements and its earlier 100,000-point double-precision timing study. The inputs, writers, energy distributions and timed sweeps differ between the two studies.
- The independent receipts for the earlier work are in `external-validation.md`, `../qed-seven-point-external.tsv`, the four `eight-point-*.md` files and `nine-point.md`. Nine-point high-statistics MadGraph tests use the subset-current evaluator. The paper's literal tensors were independently transcribed and checked across all 170 labeled photon assignments.

## Export the grouped SPINAS process

Build `hepcat_reduce` from `csource` in Release mode. Compile `export-rate-family.cpp` and `time-rate.cpp` separately using the same include directories and link libraries as the native QED driver. On the Apple Silicon test machine the commands from the repository root are

```sh
study=tests/benchmarks/publication-qed
native=tests/results/native-reduce-build
out=tests/results/qed-rate-replay
mkdir -p "$out"
for tool in export-rate-family time-rate; do
  clang++ -std=c++17 -O2 -Icsource -I/opt/homebrew/include "$study/$tool.cpp" \
    "$native/libhepcat_reduce.a" -L/opt/homebrew/lib -lgmpxx -lgmp -o "$out/$tool"
done
"$out/export-rate-family" 1 5 4 "$out/eeAAAAA-physical"
```

Arguments are the number of charged pairs, number of photons, model number and output directory. For nine legs supply a final directory containing one uncompressed native `.expr` named for each photon word from all positive to the balanced or nearest-balanced representative, from the chosen pole preference. The exporter checks that the resulting dispatch table covers every labeled photon assignment.

Use a **double-precision** SPINAS build in all compilation steps, with matching headers. The bridge assumes the writer's parameter order `Me, EE`. For a direct shared library on macOS, compile the generated `process.cpp` and `rate-spinas-bridge.cpp` with `clang++ -O2 -std=c++17 -dynamiclib`, include the generated directory and SPINAS headers, and link the static SPINAS library. For larger builds the direct measurements also compile individual component definitions in separate translation units with the same flags. Both the double and conditioned forms of a templated component must be instantiated.

The operand-table build reduces compiler memory use. It compiles the C++ operation in each distinct generated assignment and supplies its integer subscripts as read-only data. Long left-associated sums use a loop in the same operand order. The remaining helicity, conditioning and normalization code comes directly from the export. The integer-table dispatch and temporary storage can change throughput. Both build types are identified in the tables. To build a table library, run

```sh
python3 "$study/build-rate-plan.py" "$out/eeAAAAA-physical" "$out/eeAAAAA-plan" \
  "$SPINAS_INCLUDE" "$SPINAS_DOUBLE_LIBRARY"
```

## Measurement environment

The runs used an Apple M3 with 16 GiB of memory under macOS 26.6.2. The SPINAS survey used Apple Clang 21.0.0 at `-O2` and native double precision. MadGraph 3.8.1 standalone libraries used GNU Fortran 16.1.0. The per-family optimization settings are recorded in the data. CalcHEP 3.9.2 uses its native generated C modules. The seven-point archived multifermion libraries were compiled at `-O1`. New CalcHEP builds use `-O2`. The final complete-rate sweeps run one library at a time and record both wall time and process CPU time. The plots report median wall time.

## Run a matched rate comparison

Generate the MadGraph standalone process with HEPCAT's MadGraph runtime, the `sm-full` model restricted to PDGs 11 and 22, mass 1, charge 1/3 and all widths zero. The timer loads the parameter card adjacent to the chosen library, so a relocated reference uses its own inputs. Use the native CalcHEP squared-matrix-element library with the QED model in `tests/reference-models/calchep` (model 2). The rate driver sets its parameters and matches the returned external PDGs to the common leg order. Use the standalone numerical helper for large subprocesses. The archived seven-point four-fermion comparison and the six-photon comparison both use it. In CalcHEP 3.9.2 the optional micrOMEGAs build of `sqme_aux.c` adds `omgWidth[i]` for each one-based denominator index. Its array contains 40 elements. Six-photon annihilation uses indices 1 through 62. The survey driver detects this incompatible combination before evaluating the rate. The same generated six-photon process, relinked to the standalone helper, changed the relative discrepancy at the worst original momentum from 0.860 to about `6.77e-13`. The original 24 weights are preserved in `six-photon-calchep-helper.json`.

To build the standalone helper from the numerical source shipped with CalcHEP on macOS, set `CALCHEP` to its installation root and run

```sh
cc -O2 -fPIC -dynamiclib -I"$CALCHEP/include" \
  "$CALCHEP/c_source/num/sqme_aux.c" "$CALCHEP/c_source/num/ferror.c" \
  -Wl,-install_name,@loader_path/standalone_aux.so -o "$out/standalone_aux.so"
```

Link the generated subprocess objects to this helper and keep it alongside the resulting library.

Pass a JSON object keyed by family. Each inner object maps `mg`, `ch`, `physical`, `spurious`, `table_physical` and `table_spurious` to compiled library paths. Omit a library that has not been built. The MadGraph reference is required for each row. For example,

```sh
python3 "$study/run-rate-study.py" libraries.json "$out/time-rate" "$out/timings"
```

At a given momentum the SPINAS call includes `set_momenta` and `amp2`. The MadGraph call sums all massive spins and photon helicities with its standalone matrix. CalcHEP supplies its native unpolarized rate. The normalization is the initial spin average times the identical final particle factor, `1/[4 g! ((p-1)!)²]`, for g photons and p charged pairs. Momenta are constructed by the native HEPCAT phase-space sampler and rounded once to double. No generation, compilation, file access or random draws take place in the timed region. The default seed for a row is `896013 + 1000*(2*p+g) + 100*p`. Three sweeps use the same 24 points. Fast cases repeat the points until a calibration sweep takes at least 30 milliseconds. The driver records all weights, a checksum and seconds per point for each sweep. Pointwise residuals use `abs(a-b)/max(a,b)` and a relative threshold of 1e-7.

## What the source sizes count

The direct SPINAS count is `process.cpp + process.hpp`. The table build counts `plan.cpp + process.hpp + operands.i32`. The MadGraph count is the sum of subprocess `matrix*.f` source bytes. The CalcHEP count is the sum of top-level generated C modules in the subprocess output, including its service and dispatch routines. All are uncompressed bytes. Common spinor, HELAS and CalcHEP runtime libraries, benchmark bridges, phase-space sampling, event generation, validation executables and intermediate or compiled objects are excluded. The reference codes place different fractions of their operations in reusable libraries. The data therefore describe the delivered process representation and its measured cost, rather than an intrinsic lower bound on formula size.

To rebuild the numerical inventory, run `collect-rate-study.py WORK CONSTRUCTION_ROOT INVENTORY_MAP TIMINGS OUTPUT_JSON`. WORK holds the grouped sources under `spinas/{physical,spurious}/FAMILY` and the operand-table builds under `plan/{physical,spurious}/FAMILY`. INVENTORY_MAP is a JSON object keyed by family. Each value supplies `MadGraph` (the standalone reference directory) and optionally `CalcHEP` (a directory of generated C modules or a tar archive). A `ch_generation` entry can record an incomplete attempt. The collector checks diagram counts against MadGraph, counts charge-allowed cuts, retains SHA-256 source inventories and verifies all recorded spin sums point by point.

The eight-point CalcHEP squared-diagram menu listed 398 independent contributions for one charged pair, 59,150 for two, 255,024 for three and 41,856 for four. The initial generation survey allotted 75 seconds per eight-point family. Six-photon annihilation finished symbolic generation in 11,433 seconds. Its 401 generated C modules occupy 252,573,366 bytes. The three other eight-point families did not reach C output within the initial survey. A missing cell has no inferred byte count or run time. All four nine-point inputs returned exit 110 and the message `Too many particles` in the installed CalcHEP 3.9.2 symbolic parser.
