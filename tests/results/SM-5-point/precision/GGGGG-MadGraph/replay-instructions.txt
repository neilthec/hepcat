Rebuilding the numerical reference

The original double and promoted quadruple source files were identical. Compile the explicit object list in quad-same-source-build.json with GNU Fortran16 and -w -fPIC -ffixed-line-length-none -freal-8-real-16. Compile quad-stream.f90 WITHOUT promotion flags, linking the promoted objects/archives. Its explicit selected_real_kind(33) MATRIX result and input conversion preserve ABI and precision; the driver reads the archived binary64 stream first, then promotes each value exactly. It prints actual precision113, storage128, input64. Relocate only the absolute parameter-card path in the diagnostic driver to the archived card. No expression, coupling, helicity, ordering, averaging or source tensor should be edited.

Do not run make -B blindly: the standalone Makefile regenerates cuts.inc. The first diagnostic quad build encountered this; that preliminary output was not sealed. The include was restored exactly and all explicit object members recompiled. Every one of the32000 quad outputs was byte-for-byte unchanged by this restoration; only the exact-source replay is admitted in this packet.
